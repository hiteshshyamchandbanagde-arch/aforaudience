## Testing gotchas worth keeping (carried forward, still valid)

- Next.js dev-mode's `<nextjs-portal>` error overlay intercepts Playwright clicks on the bottom nav's first item - use `dispatchEvent('click')`, not `.click()`.
- `trailingSlash: true` - always include the trailing slash in Playwright URL globs against this app.
- The login form's identifier field is not `input.first()` - `MobileTopBar.tsx`'s global search input also renders on `/login` and comes first in the DOM. Target `input[placeholder*="AFA code"]` directly.
- Next 16 won't run a second dev server in the same directory even on a different port; a `node_modules` junction into a git worktree crashes Turbopack - use a real `npm ci` in the worktree instead.
- This sandbox (chat's own container, not CC's) has no installed `node_modules` - a full `tsc`/`eslint` run isn't available here for verifying direct-chat edits; `esbuild` parse + targeted grep is the fallback, with the real Vercel build as final confirmation. This session made zero direct-chat code edits (everything went through CC), so this didn't come up, but still holds.
- Locked-palette color checks are worth doing by direct grep against the actual token definitions in `globals.css`, not by trusting a component's variable *name* - `--afa-on-fill-solid` sounds generic but resolves to a specific dark-brown value tuned for one specific background; using it against a different background (as GEN-2609-027's bug did) is exactly the kind of mistake a name-only read misses.
