## Testing gotchas worth keeping, discovered this session

- **Next.js dev-mode's error-indicator overlay (`<nextjs-portal>`) sits at the bottom-left of the viewport** — the same screen region as the mobile bottom nav's first item — and intercepts real Playwright pointer clicks there. Use `locator.dispatchEvent('click')`, not `.click()` or even `.click({force:true})` (force still goes through Chromium's real hit-testing pipeline; dispatchEvent doesn't). Not a production concern, purely a dev-server artifact.
- **`next.config.ts`'s `trailingSlash: true`** means every real URL has a trailing slash. Playwright's `waitForURL('**/events')` will time out forever against the real `/events/` — always include the trailing slash in glob patterns against this app.
- **The login form's identifier field is not `input.first()`** on this app anymore — `MobileTopBar.tsx`'s global search input also renders on `/login` and comes first in the DOM. Target `input[placeholder*="AFA code"]` directly.
